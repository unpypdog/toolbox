# 工具箱 (Toolbox)

实用小工具集合，纯静态 HTML 页面，无需后端。

## 项目结构

```
toolbox/
├── index.html              # 工具箱首页
├── pyproject.toml          # 项目配置与依赖
├── uv.lock
├── tools/                  # 各个工具，每个工具一个独立文件夹
│   ├── lung-marker/        # 支气管分段标记
│   ├── rmb-upper/          # 人民币大写转换
│   ├── tax-calc/           # 税点计算器
│   ├── training-cert-batch-fill/  # 操作证书考试账号批量导入
│   └── te-cert-generator/  # TE 培训证书批量生成
└── tests/                  # 测试
```

完整的目录树（含每个文件的作用）和这个工具的**十二条硬约束**见 `CLAUDE.md`。

## 文件组织规则（开发时请遵守）

- 每个工具放在 `tools/<tool-name>/` 下，入口文件命名为 `index.html`
- 测试文件放在 `tests/` 下，命名格式 `test_<tool-name>.py`
- 首页 `index.html` 放在项目根目录
- 新增工具时：在 `tools/` 下创建文件夹 → 编写入口 `index.html` → 在根 `index.html` 添加导航卡片 → 在 `tests/` 创建测试

### TE 培训证书批量生成

填写形如 `靳睿、耿楠、芮法娟、倪文婧 南京鼓楼医院 25年10月10日` 的名单，
解析成可编辑表格，逐条核对后生成证书。

**只产出 PDF，而且完全在本机生成**：模板里的整页原图原样保留，姓名、医院、日期
由本机绘制后叠加，再由本地 pdf-lib 合成 PDF。**整个生成过程一个网络请求都不发**，
不上传任何内容，也没有次数限制（Chromium 端到端测试会断言零远程请求）。

**不提供 DOCX**：证书一旦发出去就是最终版，源文件可以被随意改动，不适合交付给学员。
工具也已经不再产出 DOCX —— 早期那条「填充 DOCX 交给云端服务商转 PDF」的路径
在本地生成成熟后已整块移除（连同为它服务的 DOCX 生成器与云端适配层）。

- **PDF**：**默认每人一个独立 PDF**（`TE操作培训证书_姓名.pdf`），
  多个文件自动**打包成一个 ZIP** 下载，解压后就是带姓名的单个 PDF。
  代价是动态文字为图像，不能搜索或选中 —— 这是换取「零字体依赖、零上传」的取舍。
- **AI 解析名单**（可选）：规则解析只认固定写法。表格粘贴、姓名与信息分行、
  一句话叙述、**手机拍的签到表照片**、**微信聊天记录截图**、以及**图片 + 文字混合**都交给 AI
  （OpenAI 兼容接口，默认 DeepSeek）。**一次可以给多张图**（最多 4 张）。
  这是工具里**唯一**会联网的功能。

### AI 与本地工作流怎么处理图片和文字

图片可能只有姓名，也可能每一行都有姓名、医院和日期；文字可能补充、修正或分组说明。
两者是**同一次颁发的同一个名单**，不是两批人。一次还可以给**多张图**
（典型用法是「聊天截图（说明都在里面）+ 一张完整名单」），AI 按上传顺序把它们编号 1..N，
每一行都会标明来自第几张图。这里不再让 AI 自己控制整个流程：

1. **AI 提取图片事实** —— 输出逐行的 `imageRows`，只报告图片中可见的姓名、医院和日期，
   并标明来自第几张图。**每张图各自逐行提取、绝不跨图去重**：去重是业务决定，不是提取。
2. **AI 提取文字指令** —— 输出 `textPeople` 和 `assignments`；每个赋值只报告字段、值、
   作用范围和原文证据，不决定是否覆盖图片。
3. **本机代码合并同名行** —— 同一个人在多张图里各出现一次时收敛成一行，空缺的医院/日期
   由另一处补上；两边都有值且对不上时不猜，两条都保留并标「疑似重复」。
4. **本机代码执行合并** —— 固定按「明确姓名 > 分组/行号 > 一一对应顺序 > 唯一全局值」
   的优先级应用文字赋值。这个优先级不受模型措辞和模型版本影响。
5. **本机代码校验冲突** —— 同等范围出现不同值、候选值无法对应、AI 标注存疑时，
   相关行直接进入「需处理」且不会自动勾选。

只有 `ambiguous` 那一种赋值算「存疑」；模型在赋值里附的解释性备注不参与判断，
否则一条**作用于全批**的赋值带个备注，就能把整张表全标成「需处理」、一条都生成不了。

文字里**恰好只有一个值且没有分组迹象**时，它代表用户主动填写的本次全局信息，会整字段
覆盖对应的图片旧值；文字没涉及的图片字段保持原样。多个候选值归属不清时不猜、不覆盖，
保留图片原值并要求人工确认。

日期允许**只写到年月或只有年**（素材里常常就没有「日」）：读到多少填多少并标
「日期不完整，请补『日』」，状态仍是需处理、不会进生成队列 —— 缺的那一段宁可空着，
也不会由 AI 编一个出来。反过来，文字日期比图上更粗且说的是同一个月时不会覆盖图上那条
更精确的日期。某一列整列都没解析出来时，面板里可以展开「**查看 AI 原始返回**」，
直接看模型给了什么、本机工作流又是怎么处理的。

所有密钥只存在本机 localStorage；默认不启用 AI。**证书生成过程不联网**，
名单、姓名、医院、日期都不离开这台电脑；只有你显式选择 AI 服务并点击「AI 解析」时，
名单内容（或图片）才会发给该服务。

#### PDF 的输出方式

**默认**：每人一个独立 PDF（`TE操作培训证书_姓名.pdf`），多个文件**自动打包成一个 ZIP**
下载，解压后就是一个个带姓名的 PDF（同名重复用 `_2`、`_3` 区分）。
ZIP 是自动的、没有开关 —— 连续触发多次下载会被浏览器拦（要你逐次点「允许」），
还得逐个确认保存位置，这不是需要用户做决定的事。

面板上唯一的开关是「**改为合并成一份多页 PDF**」（默认关）：勾上则合成一本合订本，
适合归档。默认值不能改成合并 —— 客户明确不接受合订本（收件人得自己找自己那页）。

**没有任何 API 调用或费用**：生成完全在本机完成，逐份与合并只是 pdf-lib 多开几个页面的区别。

#### 文件命名

**扩展名是固定的**：证书只交付 PDF，所以程序统一追加 `.pdf` / `.zip`，
用户输入的 `.docx` 之类扩展名会被忽略 —— 页面上不出现「选格式」这种误导性选项。

面板里的「**文件命名**」（默认收起）可以改三层的文件名模板，改完即时在下方显示示例：

| 层级 | 默认值 | 可用占位符 |
|---|---|---|
| 每人一个 PDF | `TE操作培训证书_{姓名}` | `{姓名}` `{医院}` `{日期}` `{序号}` |
| 合并成一本 PDF | `TE操作培训证书_{份数}份_{时间}` | `{份数}` `{时间}` |
| 多个 PDF 的压缩包 | `TE操作培训证书_{时间}` | `{份数}` `{时间}` |

- **单行覆盖**：预览表格里的「输出文件名」列可直接编辑，用于个别证书的特殊命名。
  它只在当前批次有效、不跨批次保存；清空即恢复批量规则。
- **去重仍然是自动的**：同名会加 `_2`、`_3`，且预览里显示的文件名、
  下载下来的文件名**用的是同一个名字**（靠 `record.fileBase`）。
- 全局模板存在本机 localStorage，和 AI 密钥分开存；「恢复默认命名」一键还原。


#### 名单解析的三条路

| 方式 | 适用 | 联网 |
|---|---|---|
| 规则解析（默认） | 顿号隔开姓名 + 医院名以「医院/卫生院」等词结尾 + 标准日期 | ❌ 免费离线 |
| AI 解析文本 | 表格粘贴、分行、一句话叙述、含职称工号…… | ✅ 需自备 Key |
| AI 解析图片 | 手写签到表、微信聊天记录截图等，**一次最多 4 张** | ✅ 需自备 Key |

**AI 结果同样要过校验**：缺姓名/缺医院/日期非法的一律红标，绝不静默进生成队列；
模型自己标了存疑的行会额外显示「AI 存疑：…」，并禁止自动勾选。但**请务必对着原图核对姓名**——
证书印错名字不可挽回，校验只能查"缺不缺"，查不出"看错没看错"。


#### 生成方式

| | 状态 | 说明 |
|---|---|---|
| **本机直接生成** | ✅ 已用 Chromium + Word 参照验证 | 唯一路径。零网络请求，动态文字为图像（不可搜索），依赖本机微软雅黑 |

> 早期还支持把 DOCX 交给云端服务商（ConvertAPI / CloudConvert / Adobe PDF Services）
> 转成带可搜索文字的 PDF。本地生成成熟后这条路径已**整块移除**：
> 它的唯一好处是可搜索文字，代价却是一整套云适配层、密钥存储、服务商下拉框、
> CSP 白名单，以及只为特定转换引擎成立的排版补丁。

#### 用之前先看

- 本机生成可直接双击 HTML 使用（模板走 base64 载荷，`file://` 下照常可用）。
  只有 **AI 解析**建议用 http(s) 打开：`file://` 的 origin 是不透明的 `null`，
  跨域请求会被浏览器拦下，而且报错很有误导性（会说成"没有 CORS 头"）。本地起服务：

  ```powershell
  cd <项目根目录>
  python -m http.server 8000
  # 打开 http://127.0.0.1:8000/tools/te-cert-generator/index.html
  ```

修改工具前请先读 `CLAUDE.md` 里这个工具的**十二条硬约束** —— 全部是踩过的坑，
包括模板载荷同步、CSP 只放行 AI 一个域名、逐份 + 自动 ZIP 的交付形态、
「不要重新引入云端 DOCX→PDF 与 DOCX 生成器」、
AI 提示词里不许出现真实日期、「AI 只提取、代码执行合并」这条工作流边界，
以及 AI 的 `max_tokens` / 思考模式 / 截断检查这三件必须一起动的事。
